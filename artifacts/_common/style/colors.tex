% FILE: artifacts/_common/style/colors.tex
% ==================================================================================================
% THE COLOUR SYSTEM'S ENTRY POINT, and the only file a document inputs for its colours: the CCN 2026
% poster and its supplement, and every document that shares the palette (the thesis figures and
% proposal, the PINTS figure, the Royaumont posters).
%
% >>> TWO LAYERS, AND THE ORDER IS LOAD-BEARING <<<
%   1. HUES   hues/colors-values.tex -- every colour value, named after its hue. Every \definecolor.
%   2. STYLE  colors-roles.tex       -- the elements of the page, bound to hues. Every \colorlet.
% \colorlet COPIES A VALUE at the moment it is read, so the roles must follow the values. A document
% that draws the concepts of a project then inputs the colors-roles.tex of that project's binding,
% under _common/style/<project>/. Every layer is generated from the palette.yml beside it: edit the
% palette, never a layer.
%
% >>> LOADED THROUGH \RootPath <<< \input resolves paths against the working directory of the build,
% not against this file. A document therefore defines \RootPath, the path to the workspace root, before
% it inputs this file:
%     \input{\RootPath/artifacts/_common/style/colors}
%
% The palette was selected among candidate schemes injected at build time; the method is stated in
% docs/practice/posters/colour-schemes.md, and reopening the choice starts there. A candidate scheme
% loads between the two layers.
\input{\RootPath/artifacts/_common/style/hues/colors-values}
\input{\RootPath/artifacts/_common/style/colors-roles}
